Configuration & service

ScrollShift now has a deliberately small persistent configuration and a systemd service for everyday dogfooding. Event-node numbers are never persisted because /dev/input/eventN is not stable across boots or reconnects.

Install

curl -fsSL https://scrollshift.dev/install.sh | sh

Downloads and SHA-256 verifies the current Linux release, then uses ScrollShift's own hardened service installer to place the canonical binary at /usr/local/bin/scrollshift and register the managed systemd service. It may prompt for sudo. The service is left stopped until a valid mouse configuration exists. To download a verified standalone binary without changing the system, use curl -fsSL https://scrollshift.dev/download.sh | sh. Or build from source:

make test
sudo make install
sudo scrollshift devices
sudo scrollshift configure /dev/input/eventX
sudo scrollshift doctor
sudo scrollshift service install
sudo scrollshift service start

configure records the physical pointer's vendor/product identity and normalized kernel name. The daemon rediscovers the current event node automatically.

If no matching pointer is present, the daemon waits. If the stored identity matches more than one candidate, ScrollShift refuses to grab a device instead of guessing. Its own virtual uinput device is excluded from capture candidates to prevent reinjection loops.

Current format

device_vendor = 0x3151
device_product = 0x402d
device_name = Example Wireless Mouse
profile = balanced
reconnect_ms = 1000

The preferred balanced profile is intentionally frozen while longer-term dogfooding continues. Configuration stays small: expose user concepts, not every internal tuning constant.

Service controls

sudo scrollshift service install
sudo scrollshift service uninstall
sudo scrollshift service start
sudo scrollshift service stop
sudo scrollshift service restart
scrollshift service status
scrollshift service logs
scrollshift service logs --follow
sudo scrollshift service enable
sudo scrollshift service disable
Current permission model. Early releases use a root system service for evdev capture and uinput creation rather than broadly loosening access to input devices. A less-privileged model can be evaluated later without weakening the initial safety boundary.

Update and uninstall

curl -fsSL https://scrollshift.dev/update.sh | sh
curl -fsSL https://scrollshift.dev/uninstall.sh | sh

Ordinary uninstall keeps /etc/scrollshift. Run the uninstall script with --purge only when you explicitly want to remove the saved mouse configuration too.
